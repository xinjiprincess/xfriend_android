     或使用独立新环境并保留原续期环境。同步后验证服务 Python 可导入 aiohttp/cryptography/PIL，

3. 数据、systemd 与 env
   - 维护窗口内先停止旧网关，避免新旧进程同时使用同一数据库。
   - 使用 SQLite backup API 备份账本，保留相邻 trial.cache-key；不要只复制活动中的主 db
     而丢弃 WAL，不要初始化新账本，不能重置已使用的五次额度。
   - 新表自动创建，无手工迁移命令。原 tasks 保留并与 v2 共用。
   - 原始媒体目录为 <XFRIEND_TRIAL_DB>.media，例如
     /var/lib/xfriend-trial/trial.sqlite.media/。服务用户需可读写数据库、WAL/SHM、
     .cache-key 与该媒体目录。现有 StateDirectory/ReadWritePaths=/var/lib/xfriend-trial
     已覆盖默认位置；如果实际 DB 在别处，要核对 systemd 的 ProtectSystem/ReadWritePaths。
   - 继续单进程运行：无外部队列，不要启动多个网关实例或多 gunicorn worker。
     保留 Restart=on-failure、UMask=0077、非 root 服务用户及当前沙箱限制。
     正常停止会释放工作者租约，重启从检查点继续；崩溃租约最多 60 秒后可接管。
   - 保留现有 MIMO_API_KEY、XFRIEND_TRIAL_DB、PORT（默认8787）。不得将凭据写入发布文件。
   - 可选 XFRIEND_SESSION_INTROSPECTION_URL，必须是受信任 HTTPS 会话内省接口。
     必须同时配置仅服务端env的 XFRIEND_GATEWAY_INTROSPECTION_SECRET（与激活站一致，32..200无空白ASCII）。
     网关 POST {"token":"客户端访问token"}，Authorization: Bearer <服务secret>，要求返回
     {"active":true,"user_id":"与现有租约一致的canonical account ID"}。
     实际契约为 /api/v2/auth/introspect，公网代理前缀需核对；这不是 health URL。
     缺服务secret或服务凭据被拒返回503且不回显秘密；
     Android 继续使用既有 X-Xfriend-Lease。新 bearer 无配置时返回401。

4. Nginx 上传与 SSE（现有 nginx.conf 未修改，父代理按线上配置合并）
   - 当前模板 client_max_body_size 30m 会阻止长音频：v2 上传需要至少128m，建议130m。
     可仅在 /v2/reviews/ 路径启用较大上限；/v1/tasks 保留原30m兼容限制。
   - 长 WAV 上传的 location 建议 proxy_request_buffering off，减少代理落盘和等待。
     客户端可能经弱网上传，client_body_timeout 应按允许的两次读取间隔配置；
     它不是整段上传总时限。建议至少120s，结合线上资源/网络策略确认。
   - SSE location 使用 proxy_http_version 1.1、proxy_buffering off、proxy_cache off、
     gzip off；不要缓存鉴权响应。应用也返回 X-Accel-Buffering: no 与 Cache-Control: no-store。
     透传 X-Xfriend-Lease、Authorization、Last-Event-ID，不要把凭据写访问日志。
   - 现有 proxy_read_timeout/proxy_send_timeout 640s 可保留。
     SSE有 keepalive，单连接最多120s；客户端要用最后事件ID重连，或者每2秒GET轮询。
   - 参考专用 v2 location（需合并已有 Host、TLS及安全头，不是完整 nginx.conf）：
       location ^~ /v2/reviews {
           client_max_body_size 130m;
           client_body_timeout 120s;
           proxy_pass http://127.0.0.1:8787;
           proxy_http_version 1.1;
           proxy_request_buffering off;
           proxy_buffering off;
           proxy_cache off;
           gzip off;
           proxy_read_timeout 640s;
           proxy_send_timeout 640s;
           proxy_set_header Host $host;
           proxy_set_header X-Forwarded-Proto https;
           add_header Cache-Control "no-store" always;
       }
   - Nginx改动需 nginx -t 通过再 reload。本轮未修改 nginx.conf、service 或激活脚本。

5. 资源与保留期
   - 单次音频<=128MiB；图片<=10MiB；文本<=2MiB；每份清单最多100个source。
     全部音频以实际PCM样本计数累计<=3600秒，不信任客户端时长。
     推荐16kHz单声道16-bit完整WAV；60分钟约115.2MB，服务端内部90秒/2秒重叠。
   - 上传缓冲、加解密、音频帧处理会使用内存，瞬时占用高于文件大小；
     父代理按主机内存和预期同时上传数设置容量，不能只按音频文件大小估算 RSS。
   - 媒体终态后24小时，由每30秒清理循环删除；停机期间需等重启补做。
     未启动草稿24小时过期。转写、证据、结果、事件、检查点和额度账本仍保留。
     不要把“原始媒体删除”误当全量个人数据删除。备份、磁盘容量与保留策略需单独管理。

7. 回滚边界
   - 升级前备份代码、数据库和密钥；不改Android或激活站。
   - 旧网关启动会删除所有pending账本项，不理解v2检查点：不能在尚有v2预留任务时
     直接回退旧二进制。先停止接收新v2任务并让已有任务终止/完成，核对预留状态后再决定回滚。
   - 不用过期数据库快照覆盖已经产生新成功扣次的账本，否则会恢复试用次数。
     保留新表和最新账本；应用版本回退与数据恢复必须分开审查。
