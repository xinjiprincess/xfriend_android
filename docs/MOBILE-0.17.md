# XFriend Android 0.17：默认执行、输入收件箱与任务管理器

版本 0.17.0-debug / versionCode 17（2026-10-29）。同包名、同调试签名覆盖 0.16 安装，保留 `.debug` 数据。完整构建结果见 `dist/2026-10-29-execution-inbox-final3/verification.json`。

## 这一版实际改变了什么

### 1. 普通请求默认执行

- XFriend 新安装和升级后的默认会话模式都是“执行”，不再要求用户先切 Ask/Plan/Craft。XSalers 仍为执行。
- 旧保存的 `ask`/`plan` 通过 `conversationModeVersion` 一次性迁移到执行；非法值回退到执行。迁移只影响后续请求。
- 已入队或已检查点的旧任务保留自己的模式快照，不会因为默认值变化被提权、自动重发或重放；缺失模式字段的旧任务按只读 `ask` 解码。
- 用户在当前请求里明确说“只讨论/先分析/不要执行”或“先规划/只给方案”时，只把这一条请求降为只读/计划，不永久锁住会话。参数充分时直接调用已注册工具。

能力判定现在只有一个事实源：`CapabilityPolicy`。工具 schema、系统提示词和实际派发前检查都读取同一份 `CapabilityFacts`（模式、工具开关、子代理、手机工具、销售上下文、专家禁用列表），避免“提示词说有、实际拒绝”或相反。

### 2. 连续输入收件箱与独立根任务

- 发送不再因另一任务正在运行、模型测试或短暂 busy 被拦截。输入立即进入可见收件箱，得到“已接收/提交中/已提交/提交失败”状态。
- 草稿在接收时立即清空；如果提交失败，原文保留在收件箱并提供“重试”，不会覆盖用户随后输入的另一条草稿。
- 普通根任务提交时冻结当前可见历史快照，使用独立的 `rootContextId` 和 `agentMessages` 执行；它不伪装成子代理，`contextId`/`agentParentId` 的子代理契约不变。
- 队列仍最多 3 个运行槽。带独立快照的普通根任务可以并发，即使属于同一专家；团队/本机群聊仍保守串行，子代理同一 context 仍互斥。超限任务显示排队。
- 完成后只把该任务的用户消息（若尚未写入）和最终回答合并回会话；回答带 `replyToId` 指向自己的请求。乱序完成时聊天按各自消息显示状态与结果。
- 共享文件写入按规范化路径加锁；HTTP 请求不持有 UI 锁；无障碍读取与动作在服务内串行，第二次动作必须使用新快照。

### 3. 任务管理器默认隐藏

- 聊天默认不显示任务托盘/任务树。只有当前用户输入明确命令才改变：
  - 显示：`看看任务`、`查看任务管理器`、`任务都有哪些`、`显示全部任务`。
  - 隐藏：`收起任务`、`隐藏任务管理器`、`关闭任务列表`。
  - 仅 `切换任务管理器` 才 toggle；重复“显示”保持显示，重复“隐藏”保持隐藏。
- 引用、转述、网页/工具输出中的同样文字不会被当作命令。
- 管理器合并两类事实而不复制：`FriendRun`（主任务/子任务/失败/待核查）和 `PhoneRepository`（事项/提醒/文件），保留 `source + id`，支持筛选、每页 10 项分页、取消仍有明确 ID 的运行任务。
- 隐藏只收起界面，不取消、不停止后台任务。

### 4. 日期型事项与跨会话查询

- `phone_create_item` 新增 `due_date`（`YYYY-MM-DD`，按当前/指定 IANA 时区校验）。只有日期、没有通知时刻时保存为待办，不虚构 00:00 或 09:00。
- 如果模型没有填 `due_date`，但当前请求明确含“今天/明天/后天/大后天”或 `YYYY-MM-DD`，宿主会从标题/详情解析日期；不解析模糊时间。
- 返回真实事项 ID、规范化日期和时区。`phone_list_items` 支持 `kind`/`status`/`query` 分页查询，重启和新会话仍可读当前账户记录。
- 用户要求通知但缺时刻时，`phone_create_item`/`phone_create_alarm` 会先保存事项（`needs_time`），再询问时刻；通知授权缺失时也先保存事项（`needs_permission`），不会因缺权限丢掉记录。不会自动编造通知时间。
- `phone_schedule_task` 仍只发本机通知；**没有**到点自动调用模型、联网查价或运行脚本的工作流。产品不会把“明天自动查 Mac 价格”报告成已经安排。

## 5. 应用自身配置保护

执行层统一拦截 agent 修改本软件配置，而不是只靠提示词：

- 无论当前运行包是 `com.singu.xfriend.mobile` / `com.singu.xsalers.mobile` 的正式、`.debug` 或 `.qa` 变体，agent 的无障碍读取/点击、`launch_app` 都不能进入本应用或系统安装/权限/设置页面；返回 `APP_CONFIGURATION_PROTECTED`，提示用户手动操作。
- 工作区路径拒绝 `xfriend.json`、加密偏好、账户/凭据目录和越界路径；`phone_save_file` 只能写入账户隔离的手机工作区。
- 子代理继承同一执行检查；没有通用 Store/配置写工具，也没有 Intent/深链接配置工具。正常事项、提醒、文件、取消指定任务和任务管理器显示不属于配置变更。
- 用户本人手动设置供应商、密钥、权限开关、专家等页面不受影响。

| 通知/无障碍未授权 | 返回具体缺失项和设置入口；日期事项仍先保存，不伪装已授权 |
| 未实现的定时自动查价 | 提示词和工具描述明确只发通知；不报告为已安排 |

## 未验证（不能由单测冒充）

当前 `adb devices` 没有设备，软件模拟器未作为 PASS 使用。因此以下仍需安装后人工验收：

- 真实账号激活与供应商实调；不同模型是否按提示调用日期事项工具。
- 真机无障碍点击、两个动作的时序、敏感屏接管。
- 通知/准确闹钟实际送达，厂商后台限制下的任务续跑。
- 进程被杀后收件箱/队列/检查点的设备级恢复（已有 JVM 队列与恢复测试，但不是设备实测）。
- 自动定时联网查价未实现，本轮没有把它包装成已完成能力。
