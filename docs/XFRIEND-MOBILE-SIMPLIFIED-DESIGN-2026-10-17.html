MOBILE PRODUCT DESIGN / 2026.10.17

更简单的 Xfriend 手机版

打开就能找助手处理事情。保留专家、团队和电脑能力，把配置与管理收进合适的位置，让每个页面只有一个清楚的主要动作。

方案稿 · 未实施Android 优先沿用 Kotlin / ComposeXfriend 主方案 · Xsalers 配套规则

依据电脑版 1.4.13 阶段记录及 2026-10-17 的 1.4.14 候选设计增补，结合手机现有源码。文档存在或源码已写入不代表已安装、已部署或完成真机验收。

产品取舍页面示意关键流程运行与同步Xsalers实施验收

01 / 先减少用户需要理解的概念

电脑版已经把默认助手、明确的对话模式、专家管理和按需加载作为主要方向。手机继续这一思路：默认进入 Xfriend 助手，不要求先创建智能体、挑选引擎、配置团队，再开始第一句话。

三个主入口

对话：默认助手、最近会话、正在运行的任务。
专家：我的专家、团队、技能与知识、发现与导入。
我的：账号空间、模型、电脑连接、同步、外观与帮助。

从当前“对话／工作台／资源／我的”四栏收敛为三栏。技能和知识继续保留，只调整入口。

名称统一，能力仍然明确

面向普通用户统一使用“助手／专家”，不再先让用户区分“智能体”和“专家”。创建入口统一为“创建专家”；工作区、工具与执行位置在能力设置里说明。

底层 ID、工作区、原有聊天记录和团队成员关系保留；界面合并不等于合并数据实体。

保留、折叠和延后

  • 首期保留：账号登录注册、流式对话、专家／团队、技能／知识、模型测试、电脑连接、任务记录、配置包导入、已有账号与数据。
  • 折叠到二级：模型提供方列表、完整提示词、团队成员模型覆盖、技能市场、知识管理、导入冲突、同步诊断、平台账号与设备目录。
  • 电脑处理：Docker 资源调整、完整 DSH 工作区、本地脚本／stdio MCP 部署、复杂关系图、服务器管理。手机显示能力与状态，提供在电脑继续的入口。
  • 后续再做：完整手机会议编辑、声音克隆工作室、通用远程桌面深度适配、云端自主执行。现有可用入口保留在高级区域，未上线能力不占首页。

Xfriend 与 Xsalers 仍然是两个独立产品。账号可以共享，任务、客户数据和授权范围必须明确，不能为了简化界面把两个应用的数据静默合并。

视觉沿用电脑版办公风

页面底色采用 #F4F6F9，容器白色，正文 #182230，次级文字 #566477，边线 #DCE2EB。这些来自电脑版实际主题文件，而非另做一套大面积渐变卡片。

保留现有 Xfriend 图标。未设置跨端偏好的旧用户保留玫瑰品牌色；已有用户偏好则沿用。示意按钮文字使用更深的玫瑰色以保证可读性，完整配色在实施阶段做对比度验收。

移动端尺寸与手感

  • 主要控件触摸区域至少 48dp；页面边距 16dp，卡片圆角 12～16dp。
  • 正文默认 16sp、说明 14sp；支持系统大字体，关键信息不依赖浅灰小字。
  • 底栏轻度毛玻璃，内容仍清楚；设备不支持时回退半透明或实色，不做全屏实时模糊。
  • 转场使用短距离位移与淡入，约 180～220ms；尊重系统减少动画设置。
  • 键盘弹起时优先显示输入框与发送按钮，底栏收起；支持系统返回与手势返回。

这是可评审的交互方向，不是像素定稿或可安装应用。

03 / 核心页面与操作逻辑

对话：一个输入框承接日常使用

首页标题为当前专家；历史按钮打开会话抽屉，新建会话放在抽屉顶部。输入区保留“模式”和“当前模型”两个清晰入口，执行位置以小标签显示。避免顶部同时堆叠专家类型、团队、模型、电脑入口、任务横幅等多排按钮。

  • 问答：默认模式，可读已授权资料，不修改文件、不安装能力；限制由执行器实施。
  • 计划：形成步骤和所需资料，用户检查后才能切到执行。文字里出现“执行”不自动提权。
  • 执行：允许当前环境已授权的工具；新增写入／外部操作按策略确认。当前轮保存模式与模型快照。
  • 附件：使用系统选择器；预览文件、图片和识别结果。远端接口未支持附件时明确禁用该位置的发送，不假装上传成功。
  • 结果：正文流式显示，工具过程默认收起为“查看处理过程”；引用、文件、复制／分享放在结果下方。

专家：横向选择，纵向查看内容

常用专家和团队采用横向滚动卡片，卡片包含头像、名称、用途及可用状态。提供“查看全部”进入可搜索网格，解决专家很多时横向翻找困难。卡片主动作直接开始对话；长按或更多菜单编辑，避免所有卡片都把提示词与删除按钮展示出来。

创建分为基本信息、能力与资料、高级设置三个层次，默认只展示名称、用途、工作方式。提示词使用完整编辑页，支持示例与撤销；技能、知识用可搜索选择器。默认继承当前模型，只有确有需要时单独覆盖。

团队与会议：保留功能，不混淆执行语义

团队详情展示主持人、成员和目标。首期保留当前手机顺序协作，名称明确为“团队协作”；电脑版会议入口按能力检测出现，默认只读讨论。主持总结、成员发言和行动纪要分层展示。会议产生的行动需点击“转为执行任务”并确认；不自动安装技能、调用写工具或切换为执行。

完整会议编辑放在后续版本：议题必填，名称选填，成员横向选取；轮数默认继承桌面规则，高级页才设置。会议期间支持补充意见、停止与查看纪要；重连不能重复开会。

导入与市场：先看清楚，再加入自己的专家

资源导入统一入口支持已实现的电脑配置包格式；.xpack／.xfpack 必须按文件内部格式和版本识别，不能仅改后缀。蓝图另按 xfriend-agent-blueprint v1 验证，复用电脑版限制：最多 30 专家、10 团队、每团队 2～20 人、输入不超过 1MiB。纯自然语言不当可执行配置。

导入预览显示新增／更新资源、缺失模型、技能来源、运行位置及冲突。先保存停止状态，再由用户运行。让专家设计专家时同样输出草案，经预览后保存；市场描述和图片中的文字只作为资料，不变成安装授权。

04 / 状态反馈要少而准确

  • 排队、执行、等待确认、已完成、已停止、失败使用统一文案；全局只保留一条紧凑任务提示，详情进入任务记录。
  • 录音处理、文件上传、下载按已知工作量显示一个总百分比，不展示“第几段／共几段”。没有可靠总量的模型生成显示“正在生成”，不伪造百分比；完成必须在结果成功保存后才到 100%。
  • 失败给出可操作原因：模型未配置→去配置，密钥无效→修改密钥，额度不足→更换模型，电脑离线→重连，网络中断→继续查看任务。输入与已有输出保留。
  • “继续查看”恢复已有任务；“重新执行”明确创建新任务。存在不确定工具副作用时先核查，不因为网络重试自动执行第二遍。
  • 安装、导入和复盘进入后台任务；普通页面不被全屏加载遮罩锁住，取消与离开页面是两个独立操作。

05 / 手机与电脑：入口统一，执行边界清楚

此手机

负责对话界面、本地资料和已有原生工作区工具。模型通过配置的网络服务推理。保存任务和检查点，后台服务继续执行；被系统强制停止后显示中断，由用户选择继续。

已连接电脑

使用电脑实际提供的专家、模型、知识和工具。通过配对后的原生任务接口显示流式结果、待确认操作与任务状态。复杂 DSH 工作区仍可进入电脑页面。

“电脑执行”“电脑版工作台”“平台连接”的重复入口合为“电脑与平台”。电脑详情保留两个明确动作：连接后用于对话，以及打开电脑工作台。平台设备放在独立分组，平台登录与 Xfriend 账号不混为一谈。

必须先补齐的协议差异

  1. 现有 v2 合同只接收文本，尚未接收手机指定的会话模式、模型覆盖和附件。新版应通过能力协商新增字段／路由；旧服务继续兼容，未支持的控件不显示为可用。
  2. 现有文档明确内置 Go 桥当时未开放 /mobile/v2/，独立桥可用。实施前核对当前 Go 实现与安装包；必须完成“手机→实际桥→桌面网关→模型／工具→手机”验收，不能仅凭 Python API 测试判断已连通。
  3. 团队会议与普通任务是不同资源；不能把会议接口直接映射到普通 run。会议、DSH、能力安装与文件传输分别声明可用能力。
  4. 手机／电脑新会话使用各自 ID 和明确映射；电脑或模型切换需新建或明确确认，不能静默迁移运行中的上下文。
  5. 操作确认卡展示工具动作、影响对象与原因，只接受当前审批 ID 和摘要的批准／拒绝；需要改参数或回答复杂问卷时引导回电脑。

账号和同步

沿用电脑版的手机号／邮箱＋密码流程，保留注册、记住账号与保持登录；注册字段和改密策略使用真实服务器合同，不另造账号系统。账号已登录、配置已同步、电脑已连接是三种独立状态。网络或模型失败不清除账号。

默认同步专家配置、团队引用、允许同步的技能元数据与外观偏好；聊天、知识文件和原始媒体按实际合同单独启用。机密默认不随配置同步；通过电脑执行可复用电脑模型而不把密钥发到手机。用户要求复制模型密钥时逐项授权并通过受保护传输保存到手机加密存储。

以账号＋空间＋资源 ID＋版本跟踪同步，冲突可比较两版或保留副本。注销与空间切换撤销旧请求和缓存访问；语音／图片／第三方通道记录按来源隔离，不因同一个助手名称而混入同一记忆。

06 / Xsalers 使用同一套简洁规则

Xsalers 保留独立图标与紫色强调色，共用底栏、表单、弹层、任务状态、模型配置及字体规范。建议四个主入口：今日／客户／复盘／我的。专家入口移到复盘的显眼位置，“专家／团队”切换后使用横向卡片，不删除自定义专家和 AI 专家设计师。

  • 今日：只展示今日待办、需跟进客户和未完成复盘，点击就能进入对应客户。
  • 客户：详情内统一查看概况、沟通、待办、商机；画像、喜好、层级可编辑，AI 建议注明证据和日期，不覆盖人工修改。
  • 复盘：先关联客户，再选择录音／截图／文字，选择专家或团队后提交；总百分比、后台处理、录音回放、原文和报告保持在同一条沟通记录内。
  • 我的：专家与能力管理、客户导出、模型、同步、设置。客户导出先选择范围和字段，附件另选，成功后调用系统分享。

本次主方案以 Xfriend 为实现主线。Xsalers 后续复用通过验收的通用组件，不把其客户工作流改造成通用聊天首页。

07 / 实施顺序与交付门槛

第一步：界面收敛与主题基础

在现有 Compose 工程改导航、组件尺寸、颜色令牌、明暗主题、底栏及转场，保留图标和历史数据。优先完成对话、专家、我的三页和表单改造；旧入口提供可发现的新位置。

验收：360／390／430dp、深浅色、200%字体、键盘弹出均无重要内容被遮挡；主要动作48dp；正文对比度至少4.5:1；系统减少动画生效。

第二步：对话和任务闭环

修正手机模型预检查、模式硬权限、流式结果、任务记录与错误引导。保留原0.8在研代码，先核对当前构建和测试状态，再整合，不把README版本号当已交付APK。

验收：真实模型问答和工具读写完成；问答／计划不能修改文件；错误草稿保留；切后台、恢复、停止、退出登录不重复执行或串账号；未知完成状态不标成功。

第三步：专家资源与电脑连接

先打通配置包预览／导入与模型映射，再接原生电脑会话、待确认操作和资源能力检测。蓝图与会议只有在真实协议适配后开启，复杂配置继续通过电脑处理。

验收：一份电脑版真实导出包往返；同名冲突与缺模型能处理；电脑在线／离线、断线重连、重复提交、审批和多账号切换均有测试；一条真实桌面专家任务返回手机。

第四步：同步、升级和 Xsalers 复用

完成外观／资源同步合同，保留旧数据和签名，执行0.7／现有已安装版本的覆盖升级。Xsalers 只复用已稳定组件，并回归客户详情、录音、截图和导出。

验收：同账号两端增量更新、冲突、注销、离线恢复；账号／专家／团队／模型／会话数量升级前后核对；Android真机实际安装和后台测试。模拟器结果单独记录。

这一轮只交付方案和交互示意，不改业务源码、不重打 APK、不部署服务器。后续安装包版本号以完成验收的实际内容决定；云端执行未验收前不会作为默认选项。

08 / 面向工程实现的落点

ProductBrand.kt：拆分品牌与语义主题，保留原图标；AssistantScreen.kt：三入口导航与统一详情路由；FriendChatScreen.kt：输入区、流式输出、任务反馈；专家编辑和资源导入页面：分层表单与预览；FriendRemote*：能力协商、电脑会话与审批；账号／同步模块：空间隔离和偏好合并。

继续使用 Kotlin＋Jetpack Compose，不为 UI 改造切换 uni-app，也不把完整桌面网页塞进主聊天页。用共享 token 和组件规则对齐电脑版，保留 Android 原生文件选择、返回手势与权限逻辑。

交付物为两款 APK、真实界面截图、电脑版接口变更说明、升级与数据核对记录、已通过及未通过的验收清单。先完成可用链路，再扩大功能，不以按钮出现代替实际能力。
