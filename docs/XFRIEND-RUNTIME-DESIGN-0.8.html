Xfriend 智能体可靠运行
故障判断与下一版详细设计

手机能够调度智能体、调用模型和执行授权工具。当前失败不能直接归因于手机性能：现有 APK 的运行时、模型适配和远程执行接入确有缺口，需要分层补齐。

状态：源码核查与设计完成；本文件不代表新引擎已实现、已发布或真实故障已复现。用户反馈为“点击发送立即报错，显示一段文字和网络连接有问题”。本机 ADB 未连接用户手机，尚未取得请求级诊断信息。

1. 本次故障：能确定什么

立即失败优先排查模型配置和连接，而非 Android 后台省电。页面中先出现一段文字并不能证明模型已经成功回答：当前入口会先保存用户输入；团队也会先保存已完成成员的输出，再执行后续成员。

  • 登录与模型配置分离：新安装默认模型为 gpt-4o-mini，密钥为空。账号登录本身没有将 Xfriend 发送入口接到试用模型服务；没有可用模型时不能执行。
  • 专家导入不等于运行能力导入：非 native 引擎会直接报“仅支持远程桌面运行”。部分提供商需要适配器，但主发送入口仅创建 AgentRuntime(s)，没有传入模型解析适配器。
  • 手机运行时只有基础工具：普通 Xfriend 主要提供工作区列出、文件读写、知识词法检索。Python、Shell、浏览器、桌面控制及完整 MCP 运行能力没有由这个入口提供。
  • 模型协议过于单一：固定拼接 /chat/completions，并在工具可用时发送 tools。接口类型、完整 URL、模型是否支持工具调用，目前缺少预检查。
  • 任务寿命与可观测性不足：发送挂在 ViewModel 协程中，读取完整 JSON 后才保存回答；单请求总时限 90 秒。没有 Xfriend 专用持久任务恢复及逐字输出。

这些是源码事实，但不能据此断言用户本次一定是密钥错误。需要记录实际端点、HTTP 状态、网络异常类别、模型 ID、执行端和请求 ID；敏感字段不得进入日志。

依据：MainActivity.kt:93–113；Store.kt:40–42；AgentRuntime.kt:99–100、112、152–165、188、263；CompanionScreen.kt:113、145。源码根目录 D:/xfriend-suite/app/src/main/java/com/singu/xfriend/。

2. 产品目标与执行架构

保留 Kotlin / Jetpack Compose 原生界面、Xfriend 图标、账号及现有资源。使用统一任务协调器，底下连接三个执行器；用户看到的是一个助手和一致的任务体验。

手机基础执行

独立完成对话、基础专家／顺序团队、私有工作区、知识检索及授权的手机工具。模型推理通过配置的 API 服务完成；不以 APK 内置离线大模型为前提。

电脑完整执行

复用现有 Octop / Harness 引擎及电脑模型配置，执行浏览器、Shell、Python、MCP、完整专家和团队。电脑必须在线；控制电脑系统的能力不能由没有连接电脑的云实例替代。

可选云端执行

在独立服务中部署同一引擎，承接不依赖用户电脑的长任务。手机锁屏或关闭后继续运行。账号站保留身份、授权和同步职责，不把智能体进程塞进账号站。

默认策略：普通且能力完整的任务在手机执行；明确需要电脑能力的任务在已配对电脑执行；长任务可以在用户启用云执行后提交云端。运行前展示“此手机 / 我的电脑 / 云端”，用户可以锁定位置。不得在失败后静默迁移任务、上传文件或重新执行副作用工具。

电脑或云端不可用时，显示缺少的能力和连接入口；不能把原专家悄悄降级成普通提示词聊天，也不能返回“已完成”。云执行入口只有在服务配置、健康和权限检查通过后才启用。

3. 先修好模型和立即失败问题

  1. 执行前检查：检查资源存在、引擎支持、密钥引用、模型名称、接口类型、必需工具及执行端在线状态。失败在发送前给出可操作提示，保留草稿。
  2. 模型注册表：模型保存为独立配置，包含提供商协议、基础地址、模型 ID、密钥引用以及 stream / tools / vision 等能力。第一阶段手机实现 OpenAI 兼容协议；其他协议明确路由至已支持的宿主适配器，不靠品牌名称推断协议。
  3. 测试连接：用户主动点击，先验证 URL 和鉴权，再发送小型文本请求；工具调用另做小型探测。不支持 tools 的模型仍可普通聊天，工具型专家运行前提示更换模型；不能用提示词模拟工具成功。
  4. 地址处理：界面明确要求基础 URL；识别误填完整 /chat/completions，保存前提示并规范化一次，避免双重路径。电脑 localhost 地址不得直接当作手机端点；本地电脑模型通过已授权电脑代理访问。
  5. 错误分类：分别处理配置缺失、鉴权失败、无权限、模型／路径不存在、限流、DNS、TLS、连接失败、响应超时、协议错误和能力缺失。展示短提示、重试或配置入口及诊断编号。
  6. 脱敏诊断：记录安装版本、执行端、时间、URL 的 host/path、HTTP 状态、异常类别和耗时；不记录密钥、Authorization、客户原文、完整提示词或响应正文。用户可导出这份诊断，不必导出私人资料。

初始网络默认：连接 20 秒、首个有效流事件 60 秒、流空闲 60 秒。流持续有活动时不因当前 90 秒总时限中断；单次运行默认最多 30 分钟，超时保存进度并允许从安全检查点继续。处理 429 尊重 Retry-After；401、错误路径或不支持能力不自动重试。

4. 持久任务、流式输出与恢复

新增独立 RunCoordinator 与 RunStore，UI 只提交任务、观察状态和发送操作。资源仍保留 0.7 的稳定 ID，任务保存输入与配置快照，运行期间的资源修改不改变正在执行的任务。

Run：run_id / client_request_id / thread_id / resource_id / resource_revision
     target / state / last_event_seq / checkpoint_ref / partial_output / error_code
状态：排队 → 运行 → 等待用户确认或手机工具 → 完成
      也可进入可恢复中断、失败、取消；网络断开与任务失败分开表示。
Event：run_id / seq / type / payload
事件：状态、文本增量、工具开始／结果、确认请求、错误、最终结果。
  • 手机任务：用户在前台发起时启动符合用途的前台服务；每个完整模型回合、工具结果和可恢复步骤持久化。WorkManager 负责待发送资料和恢复协调，不承诺突破系统强制停止或无限常驻。
  • 远程任务：提交得到 run_id 后由电脑／云端执行，不依赖手机连接持续存在。手机重新打开后按最后已保存的 seq 取回事件；桌面已有聊天 WS 和 trajectory 可复用，但现有弱恢复还需补齐持久重放。
  • 流式界面：显示逐字文本、简短动作说明、可取消按钮和确认卡片。一般智能体没有可信固定总步数，使用“运行中”和文本流；只有录音处理等已知工作量显示真实百分比，不编造进度。
  • 恢复边界：手机进程退出会中断正在进行的本地模型请求。恢复到最后完整检查点，保留未完成文本并标明；不能宣称续上了供应商已经断开的同一条生成连接。
  • 副作用：同一 client_request_id 不能创建两次任务；模型或工具调用已有 operation_id 和完成记录。响应丢失且执行结果未知的写入／发送操作进入待确认，不盲目重放。
  • 并发与隔离：一个会话同一时刻只运行一个任务；手机本地同时一个任务，其余排队。每个任务绑定账号、空间、执行端和工作区；切换账号不把旧事件显示到新账号。

Android 官方说明：页面协程不具备持久后台执行保证，WorkManager 和前台服务各有适用场景与限制；Doze 会限制网络和 CPU。参见 后台任务指南、Doze 与待机指南。这些是后台可靠性约束，不能作为“点击即报错”的既定诊断。

5. 电脑／云端接口与身份

通过同一 v2 接口连接电脑和云引擎。旧 /mobile/status、配对桥和 WebView 保留兼容入口；原生任务接口不能只通过“打开 /chat 页面”来替代。

GET  /mobile/v2/capabilities
GET  /mobile/v2/resources?kind=agent|expert|team
POST /mobile/v2/runs
GET  /mobile/v2/runs/{run_id}
GET  /mobile/v2/runs/{run_id}/events?after_seq=...
POST /mobile/v2/runs/{run_id}/cancel
POST /mobile/v2/runs/{run_id}/approvals/{approval_id}

Python API 层实际使用 /api/mobile/v2 前缀，电脑连接桥代理为上述 /mobile/v2。创建请求最少包含 client_request_id、thread_id、resource_id、resource_revision、输入及已授权附件引用。账号／空间从已验证的会话获得，不相信客户端任意填写的 owner ID。事件先落库、后推送；客户端按 run_id + seq 去重，发现游标失效则取任务快照后继续。

配对将手机设备绑定到具体电脑、账号和空间，交换可撤销的短期执行凭据；继续保留系统信任的 HTTPS，USB 环回使用现有例外。云账号令牌不能直接当作电脑本地 JWT，需由电脑明确映射已登录身份。扫码配对显示电脑名称和授权范围，并可在电脑撤销。

云端使用独立运行服务验证同一云账号和产品权益，通过能力接口公开实际可执行能力。仅同步账号和配置不会启动智能体。试用由服务端按整次 run 预留额度，相同任务重试不重复占用；BYOK 与订阅额度分别显示。共享试用密钥继续只在服务端保存。

原生 API 是本设计新增合同，当前尚未实现。现有桌面可复用 /api/agents/{agent_id}/chat/ws、Gateway、Harness、history/trajectory；业务编排放在 infra，API 和 Go 桥保持薄适配，不复制第二套桌面引擎。

6. 资源、工具与移动交互

  • 资源类型：AgentResource 明确区分 agent / expert / team，并保留模型绑定、工具权限、技能、知识、团队执行模式和 required_capabilities。旧 agent- 标识迁移为类型字段，保留原 ID、工作区与历史。
  • 专家包兼容：沿用 .xfpack v1/v2 和 _xfpack 扩展；增加能力映射旁车信息，不擅改原包。导入先展示“手机可运行 / 需要电脑 / 需要补模型”，团队任一成员的能力缺失在运行前处理。
  • 工具注册：每个工具声明执行端、输入输出和是否需要确认。手机提供工作区与知识等已实现工具，并逐项接入授权文件选择／共享和录音；浏览器、代码、MCP、电脑文件与控制通过宿主引擎提供。
  • 权限确认：读取所选文件和作用于工作区按已有权限执行；外部发送、删除和系统控制显示具体操作卡片再确认。手机传感器或系统权限操作进入等待手机状态，不让云端伪装已经完成。
  • 团队：手机第一版明确支持顺序团队并保存成员结果；复杂路由／并行协作按包的原始模式交给支持的宿主。不能将所有团队一律改成提示词串接。
  • 入口：聊天页顶端展示当前助手／专家／团队与运行位置；选择采用横向卡片或底部面板。主输入区始终可用，发送中提供停止、查看任务和结果文件。
  • 首次使用：登录后给出“使用试用 / 配置自己的模型 / 连接电脑”。分别显示是否可用和原因；不让新用户面对空密钥配置后点击发送才失败。

7. 实施顺序与验收标准

  1. 第一阶段：故障定位与手机基础闭环。先取得实际失败分类；补预检查、模型测试、错误诊断、流式模型适配和密钥映射。验收真实模型能回答、调用文件写入／读取、检索知识，工具轨迹和文件结果可核查。
  2. 第二阶段：本地任务可靠性。引入 RunStore、前台执行、事件持久化和安全检查点。覆盖旋转、切后台、短断网、进程终止恢复；本地进程被终止时状态诚实显示可恢复中断。
  3. 第三阶段：原生电脑执行。完成能力发现、配对身份、任务 API、持久事件重放和确认交互。真实导入一个依赖浏览器或代码工具的电脑专家，在手机提交、电脑执行，结果回到手机。
  4. 第四阶段：可选云端长任务。独立运行服务部署、产品权限与额度接入。手机关闭 30 分钟后重新打开，远程任务仍可查看状态和结果；执行位置固定，不因重连产生第二次运行。
  5. 最后：升级与发布。覆盖升级 0.7，不删除原账号、专家、团队、模型和聊天历史；两款共有代码同时回归，签名与包名延续。提供错误诊断样例、真实任务轨迹、APK 和验收报告。

必须通过的场景

  • 空密钥、错误模型、重复端点、401/403/404/429、TLS、DNS、超时分别显示准确原因；失败后草稿仍可重发。
  • 支持工具和不支持工具的模型分别验证；无工具模型可聊天但不会假装完成文件、浏览器或系统操作。
  • 慢响应超过旧 90 秒阈值仍能在有活动时持续输出；截断、空回答、异常结束不标完成。
  • 原生／非原生专家、缺密钥提供商、复杂团队及电脑离线都有清晰路由，不静默降级。
  • 手机锁屏／进程终止、电脑重启、网络恢复和重复提交不造成重复工具写入或重复占用试用次数。
  • 任务、文件、模型秘密和事件按账号／空间隔离；撤销配对和切换账号立即失去旧执行权限。
  • 至少使用两个真实模型服务、一个真实电脑、一个实际 Android 手机完成端到端验收；模拟响应和界面截图只能补充，不能替代这些结果。

前轮每款 174 项测试主要证明已有代码与模拟协议路径通过，不代表手机真实模型、完整桌面专家和长任务已全部验收。本次实施完成的标准应升级为上述真实任务闭环。

8. 当前结论与发布条件

当前没有证据说明手机硬件导致故障。更明确的问题是手机入口尚未接上完整运行体系，且报错信息无法支持准确诊断。先修模型接入和诊断，再用统一任务层连接手机、电脑和云端，才能同时满足独立基础使用与完整专家能力。

本设计保留现有 UI 技术栈；换成 uni-app 不会自动补齐引擎、模型适配或后台可靠性。完全离线模型、在 APK 内打包整套桌面 Python 环境、任意脚本执行及无限后台常驻不作为本轮前提。

部署条件：账号站已有同步接口不等于存在云 Agent 引擎；云执行需独立服务、健康检查与真实验收后才启用。此前 113 主机身份和 HTTPS 的待核验事项属于部署前置条件，不能绕过或在界面伪称已可用。

核查方式：阅读手机版发送入口、运行时、模型存储、电脑配对及测试；阅读桌面聊天 WS／恢复逻辑；检查 ADB 连接为空。此轮未修改运行代码、未部署、未调用用户模型 API，未产生新 APK。
