Xfriend / Xsalers 电脑端协作清单

Android 0.5.0 · 2026-10-13。此文区分手机已经实现的能力与需要另一端开发的内容。

手机当前提供

两个独立包，共用账号、模型调用、手机运行时与配对协议。Xfriend 包名 com.singu.xfriend.mobile；Xsalers 包名 com.singu.xsalers.mobile。手机可导入 DesktopBundle v1 专家、团队、技能、知识和模型配置，提交失败会回滚导入；用户可选择是否接受密钥。

Xsalers CRM 当前为手机本地数据，含客户、沟通记录、商机、跟进。两个应用通过同账号、同工作空间的加密迁移包迁移资料。该迁移包不是电脑增量同步协议。

优先级 1：完整桌面资源导出

电脑版实现带登录权限及资源所有权校验的 GET /api/mobile/export。现有配对桥通过 /mobile/export 提供给手机；不要让客户端直接访问数据库。

精确字段、类型、长度限制和引用关系以 mobile-export-v1.schema.json 为准；示例见 示例 JSON。保留原始资源 ID，团队成员必须指向实际专家，技能与知识引用必须可解析。模型配置导出应由用户明确选择是否包含密钥，日志不得记录密钥。

验收：同一导出连续导入两次不重复；只导出当前用户的资源；不接受密钥时保留手机原有配置；失败时保持导入前状态。

优先级 2：账号与试用

手机保留原登录注册及签名授权协议，当前兼容原 singu-xfriend 产品授权。账号后台需要新增 Xsalers 独立产品权益，并约定旧用户资料与会员迁移政策；完成后手机再切换授权产品标识。

五次试用的共享模型密钥仅留服务端。现有 trial-gateway 实现额度与幂等任务逻辑，需修复公网 HTTPS 可达性后联调。2026-10-13 检查入口超时，不能将服务端本机健康视为手机可用。支付尚未接入。

验收：同一请求重试不会重复扣次数；并发不会超额；额度耗尽返回明确结果；APK 与客户端响应中不包含共享密钥。

优先级 3：CRM 同步（待双方实现）

建议以用户和工作空间隔离 customers、communications、opportunities、followUps，媒体使用授权上传下载。每条资源保留稳定 ID、服务端版本、更新时间及删除标记。服务端提供游标增量拉取与带基础版本的幂等写入；冲突返回双方版本，由用户确认。

这是后续协议设计建议，当前手机未调用 CRM 同步接口。另一端不要把以下建议接口当作已实现约定：GET /api/mobile/crm/changes?cursor=...、POST /api/mobile/crm/batch、媒体上传及下载接口。实现前应共同冻结 Schema、错误码、时区、分页和冲突策略，并更新 Android 客户端。

验收至少包含断网后恢复、双端编辑冲突、删除恢复、多账号隔离、重复推送、媒体失败后重试与分页不漏记录。

远程电脑与权限

保留现有 /mobile/status、/mobile/pair、/mobile/export、/mobile/logout 配对接口和用户授权流程。远程电脑操作在电脑环境执行，手机本地智能体工具在手机授权的工作区执行；两端分别呈现运行状态与操作结果。

现有适配器、部署脚本及原协议说明见 desktop-bridge/ 与 DESKTOP-INTEGRATION-0.4.html。不得将桌面管理员权限默认授予所有手机版账号。
