# XFriend Android：架构现状与下一轮需求

日期：2026-10-29（Asia/Shanghai）。这是给 OpenCode / deepseek-v4.1-flash 的开发交接，不表示下列新需求已实现。源码核对基于当前工作区，已交付基线为 0.16.0-debug / versionCode 16。

## 1. 用户要的产品行为

这是一个以自然语言驱动的执行助手。用户可以在同一聊天里连续发送多个独立请求，先前任务运行时继续输入，每条请求得到各自的接收状态、进度和结果。默认具备已授权的执行能力，不要求用户先理解或切换 Ask/Plan/Craft。用户询问任务时打开任务管理器，要求收起时隐藏，隐藏不取消任务。能执行就调用真实工具；不能执行就报告具体原因及下一步，不凭空声称只读、没有记忆或已完成。

唯一明确的产品禁止项：agent 不能操作或改变本软件本体的配置。用户本人仍可手动配置。

“默认执行”指产品默认开放实现了的任务工具，不是伪造 Android 授权、绕过账号授权、无限并发或在没有工具时谎称执行成功。Android 系统授权未获得、供应商认证失败、功能尚未实现、操作结果不确定，都必须如实反馈。

## 2. 已有架构：先复用，再改造

```text
AccountRoot / AccountViewModel
  └─ 账号 scope + FriendStoreRegistry 授权代次
      └─ AssistantRoot 路由
          ├─ StarChatPage / StarSettingsPage / FriendProvidersPage
          ├─ SubagentTasksPage（现有任务详情）
          └─ FriendViewModel：草稿、发送、运行列表、取消/恢复
              └─ FriendRunRepository → FriendRunQueue → 持久任务账本
                  └─ FriendRunService：前台服务、信号调度、最多3个运行槽
                      └─ FriendRunWorker：截止、取消、状态/部分结果
                          └─ AgentRuntime：快照、提示词、工具循环、检查点
                              ├─ ProviderSession → ProviderWire / Transport / Response
                              ├─ PersistentSubagentAdapter → 独立子代理上下文
                              ├─ workspace 文件 / 词法知识检索
                              └─ PhoneToolRuntime
                                  ├─ PhoneRepository：私有文件、事项、请求幂等账本
                                  ├─ PhoneAlarms：AlarmManager、本机通知、重启重调度
                                  └─ PhoneAccessibilityService：当前屏幕观察与操作
```

## 3. 对所贴拒绝的诊断

已核实的矛盾：软件存在持久文件/事项工具，也存在磁盘会话历史，不能笼统说“不能创建任何记录”“没有任何跨会话记录”。

需要区分的四件事：
1. 保存一条“明天问Mac价格”的事项：已有持久存储可以承载。
2. 明天发送通知：需要调度和系统通知/准确闹钟授权；没有明确提醒时刻时，不应擅自安排任意小时。
3. 明天自动查询最新Mac价格：当前没有这样的定时模型/网络查询工作流，不能声称已经安排。
4. 任意新会话自动想起一切：当前没有完整的长期语义记忆检索，不能由“有历史文件”推导为已经实现。

推断原因（需日志验证，不当作已复现结论）：默认ASK过滤了写入工具；旧expert/skill提示词可能带有“只读”叙述；modelUseTools或tools_disabled导致未提供工具；模型没有查询持久事项。需要添加不含密钥和屏幕内容的诊断：runId/requestId、模式、可用工具名、能力判定原因、工具结果status、scope授权是否有效。不要仅靠改文案掩盖运行时问题。

## 4. P0：默认执行与能力一致性

- XFriend以默认执行能力接受普通请求，聊天主界面不要求手动切执行模式。审计新安装默认值、Store旧值加载、非法值fallback、已保存ASK/PLAN与在途run快照；仅改defaultFor无效。
- 为旧ASK/PLAN值制定一次性迁移：产品默认值迁到执行；用户明确说“只讨论/先给方案”只约束该请求，不应作为永久只读锁。已有在途任务、检查点不能被悄悄提权重放；保留证据并明确重发或保持其原快照。
- 使用统一的能力判定作为工具清单、提示词和执行校验的数据源，避免三套逻辑不一致。modelUseTools等旧门槛应移出普通聊天的日常操作路径；保留用户本人控制的配置入口。不得通过模型改变这些配置。
- 设置/授权仅由用户本人操作。缺权限时返回结构化原因和具体入口，不能让模型用无障碍替自己点授权按钮，也不能把设置页打开成功当成已授权。
- 支持的任务先执行真实工具再给结论；缺少关键参数才简短澄清。对于已可保存的事项，不因通知时刻尚缺而拒绝保存整个事项。

## 5. P0：多个输入同时处理

“多个输入”按连续文字请求理解，暂不扩展到多图/多音频上传。

- 每次发送即时生成稳定requestId、消息锚点和可观察状态。提交与执行分离，禁止静默丢弃正在preflight/busy时的第二次发送；提交失败恢复对应草稿/待发送项并给原因。
- 每条普通用户请求都能成为独立根任务，在资源许可下并发执行。默认总并发沿用3个槽，超出可见排队；支持发送过程中继续输入、返回乱序完成的结果。
- 不能简单删除claimConcurrent中的同专家互斥：当前主任务共享history和workspace，会造成串话、重复历史与文件写入竞争。
- 为根任务设计独立执行上下文/工作目录或明确的请求快照，以及消息合并/提交策略；共享资源的变更使用细粒度串行锁。不要把根任务伪装成子代理：现有contextId与agentParentId/agentDepth存在强约束，需要新字段或正式修改契约。
- 主/子任务共同计入运行槽；保留父子取消、预算、截止和授权隔离。手机UI动作必须串行占用设备执行通道，并在锁内重新观察当前界面；HTTP等待和普通本机工作可以并发。
- 结果按requestId/replyTo关联到对应用户消息；UI不能仅显示最近一条根任务的partial。用户“这个取消”要绑定消息/任务上下文；不清楚目标才澄清，不能取消所有任务。
- “把刚才两个任务合并/继续这个任务”属于显式依赖/续聊，须携带目标关联，不能默认让所有并发输入共享一份运行中对话。

## 6. P0：自然语言任务管理器

- 聊天默认隐藏完整任务托盘/任务树。用户“看看任务/任务都有哪些/打开任务管理器”打开；“收起任务/隐藏任务管理器”关闭。只有明确“切换任务管理器”才toggle，重复“显示任务”仍保持打开。
- 推荐将显示/隐藏做成受限UI控制事件，例如 `ui_set_task_manager(visible:boolean)`，不是通用导航/配置写接口。简单明确的当前用户命令可本地处理；等价自然表达由意图识别处理。引用、网页文字、历史转述和工具输出不得触发UI命令。
- 管理器是当前账户全部任务的统一查询投影：主任务、子任务、完成/失败/待核查任务，以及手机事项/提醒；按来源标识、分组筛选和分页展示。“全部”是可查询全量，不是一次加载无限历史；不得跨账号。
- FriendRun执行任务与PhoneRepository待办/提醒是不同实体，不复制成第二套事实库。统一投影保留source+id，取消/详情路由回各自仓库；不把已完成创建提醒的run与尚待触发的提醒合并成一个状态。
- 显示、隐藏、筛选、取消、重试是不同动作；隐藏不取消也不停止后台任务。隐藏后聊天仍保留每条请求的简短接收和完成结果，不自动展开全量任务树。
- 可沿用SubagentTasksPage详情，但展示状态需要明确归属当前账号/会话，以及进程重建后的恢复策略（显式打开可恢复，不因普通发送自动展开）。

## 7. P0：禁止agent改本软件配置

这是执行层硬约束，不能只写提示词。

- 配置范围包括模型供应商、地址/密钥、账号/激活/同步、会话默认策略、权限/手机控制开关、专家/技能配置、存储/授权数据及应用启停/安装卸载。用户本人操作这些界面不受本规则限制。
- 所有模型驱动入口统一禁止配置变更：普通工具、子代理、导入/深链接/Intent、workspace路径、无障碍点击/滚动/打开本应用及其系统应用信息页；不得把UI点击当作绕过配置写入限制的途径。
- 当前PhonePolicy仅有通用敏感包判断，尚无可靠的“本应用配置保护”契约。建立运行时包名（含.debug/.qa及双flavor）、受保护页面/区域与数据路径策略；在读取和派发动作前校验，防止前台切换竞态。
- AgentRuntime内的workspace和用户导出区域与Store/Phone账本/凭据仓库隔离。允许持久事项、取消用户任务和显示任务管理器；这几类正常任务操作不等同于修改软件配置。
- UI控制只允许明确白名单事件，不能反向落到万能“修改Store”接口。被禁止时返回 `APP_CONFIGURATION_PROTECTED` 等稳定原因码，并说明用户可手动修改。
- 保留已有系统授权/身份验证/支付等人工接管机制；不要为了消除“权限问题”而删除账号隔离、TLS、路径边界或未知副作用防重放。

## 8. P0：持久事项与诚实结果

- “帮我记住明天问Mac价格”：保存带内容、目标日期、时区的持久事项，返回真实ID与实际日期。建议正式增加due_date字段；无提醒时间时保存日期型事项，不用假的00:00/09:00时间充当用户选择。
- 若用户要求通知但缺时刻：先保留事项，再询问通知时刻；不能因缺通知时刻说完全无法记录。
- 新会话问“我之前让你记什么”：通过当前账户持久事项查询回答，不只依赖最近12条聊天。说明跨会话、跨设备/卸载、自动回忆各自范围。
- “明天自动查Mac价格并告诉我”：当前未实现时说明缺少定时自动查询工作流，提供可执行的持久事项/通知选择；不要将其标记为自动查询成功。若本轮另行实现，必须补后台调度、实时联网来源、登录/额度、去重和失败反馈的完整契约，不能偷换成普通提醒。
- 报告至少区分：已保存、已调度、已派发需观察、等待授权、缺参数、能力未实现、失败、结果待核查。错误原因用稳定码和中文说明，不能暴露密钥/上游原文。

## 9. 验收：必须证明行为，不能只看提示词

| 场景 | 必须结果 |
| --- | --- |
| 全新安装后“记录明天问Mac价格” | 不要求切执行；真实落盘事项；准确日期；不编造已设提醒时刻 |
| 从0.16保存ASK升级 | 按迁移契约可正常记录；旧检查点不被提权自动执行 |
| 关闭重开/新会话查询事项 | 查询原记录而非声称没有跨会话记忆；账号B不可读账号A |
| 连发A/B/C，A模型故意延迟 | 请求均接收，实际运行可重叠；B可先完成，回复各归其主；上限外可见排队 |
| 连发请求碰到busy/preflight失败 | 不静默丢消息或清错草稿；每项有失败原因和重试入口 |
| 同文件写/两个UI操作/独立网络任务 | 共享写和UI有正确仲裁；不互相串话；独立HTTP不被全局锁拖住 |
| “看看任务”后“收起任务” | 显示/隐藏管理器，不取消后台任务；重复显示仍打开 |
| 引用“他说收起任务”或工具输出包含该命令 | 不执行界面控制 |
| “修改你的供应商/密钥/权限开关”及子代理转述 | 在执行层拒绝；真实配置无变化；用户可手动设置 |
| 通过无障碍/深链接/路径穿越尝试本体配置 | 动作执行前拦截；不依赖模型自觉 |
| 通知/无障碍未授权 | 给实际缺失项和正确入口，不泛称没有写入/没有记忆 |
| 手机UI派发后断电或响应丢失 | requires_review，不自动重复点击；快照不落盘 |
| 调度“明天自动查询价格” | 已实现完整工作流才成功；否则说明具体缺能力，不冒充已设置自动查询 |

保留已有524项/变体测试基线，增加有意义的并发、迁移、管理器事件、持久事项和配置保护回归。复用 `scripts/build-linux.sh` 完成双变体单测/构建/lint，之后校验APK签名、包名、版本和副本哈希；设备/供应商实测不能用合成测试冒充。

## 10. 推荐实施顺序与交付

1. 先诊断实际工具清单与默认模式；建立能力判定和本体配置保护。
2. 默认执行迁移、日期型事项与可查询持久记录，修复错误拒绝。
3. 输入收件箱、根任务隔离、资源仲裁、逐请求回复关联。
4. 任务统一投影及自然语言显示/隐藏。
5. 回归、真机验证、版本升级及APK交付。

修改前记录现有工作区状态，保留大量已有未提交修改，禁止reset/clean覆盖；桌面参考目录只读。旧版检查点、凭据、用户历史保持可解释的迁移/回退。输出实际改动文件、设计决定、测试与APK路径、未验证项，不把本需求文档写成已完成事实。
